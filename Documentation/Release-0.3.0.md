## 本版完成

| 原问题 | 本版处理 |
| --- | --- |
| LUT 对比两侧不同步 | 移除第二个播放器；原片和处理画面来自同一次解码请求，比较线保持屏幕左右方向。 |
| 预览不能代表输出色彩、声音 | 新增“核对导出效果”：从成片当前位置生成最多 5 秒的真实导出样片，使用相同的色彩、字幕、音轨和编码流程，并显示实际输出参数；不入队、不改原片。 |
| 色彩选项只有标签、缺少真正 HDR 转换 | 内置 zimg，执行色域、传递函数和范围转换；提供 Rec.709、Display P3 SDR、Rec.2020 PQ/HLG，以及 HDR→SDR 高光压缩。 |
| 把 LUT 文件名或相机型号当作 Log 识别 | 仅明确的拍摄曲线元数据作为自动识别证据；未知时要求手动声明或确认，明显不匹配的 LUT 阻止导出。文件名只作提示。 |
| 只支持 3D LUT | `.cube` 支持 1D、3D、1D+3D Shaper，保留独立阶段和输入范围，不把大 Shaper 粗略烘焙进小网格。 |
| 12/16-bit 输入误显示成 10-bit | “跟随源”显示真实源位深；软件 HEVC 新增 12-bit 输出。不支持的 16-bit 保留组合要求明确选择，不静默降级。 |
| 多音轨目标体积低估 | 累加全部保留音轨；复制音轨采用其实际码率，未知则拒绝目标体积模式。预算预留封装开销；附件、数据轨道单独设限。单位改为 MiB。 |
| GOP 固定按 30fps 计算 | 跟随实际源帧率；59.94fps 的两秒 GOP 为 120 帧，并保留基于时间的强制关键帧条件。 |
| 预听的增益、变速音高与导出不一致 | 变速或超过 100% 增益时，预先生成与导出使用相同处理链的音频。主播放器仍监听一条选中音轨；样片支持切换导出的多条音轨。监听音量独立。 |
| 剪辑后的字幕、外部字幕及偏移受限 | 文本字幕按输出时间线切分、重排、缩放时间和应用偏移；支持外部文本字幕烧录及软字幕导出。 |
| 剪辑后章节丢失或时间错误 | 章节按删剪、顺序、复制和变速重新映射，可选择保留；不再直接沿用原时间戳。 |
| 快速裁切静默带入多余画面 | 扫描并复查关键帧，未对齐时禁用快速导出，提供“向外对齐关键帧”操作；精确裁切使用压缩导出。 |
| 默认 B 帧造成成片起点偏移 | 修复强制将解码时间移到零导致的约 67ms 画面偏移；允许编码器必要的解码预卷，使显示时间与字幕、章节共用零点。 |
| 附件保留开关与实际映射不符 | 同时尊重全局保留开关和逐轨道选择，避免附件重复映射。 |

## 尚保留的边界

- 主播放器是实时参考，尚不是完整、经过显示器校准的色彩管理预览；最终效果需使用真实导出样片核对。高位深兼容代理可能降至 10-bit，但导出读取原片。原生播放器不支持的成片格式提供真实样片文件，不伪装为低位深替代品。
- 动态 HDR：完整源片快速导出新增元数据检查及视频包 SHA-256 核对。压缩导出需明确允许移除动态元数据；只允许已标明兼容底层的 Dolby Vision 8.1/8.2/8.4 进入转换流程。**不会重建 Dolby Vision/HDR10+ 动态元数据，也不会重新测量或生成母版亮度元数据。** 尚无真实动态 HDR 相机样片验收；探测仅抽查前段帧，不能保证识别仅在后段出现的元数据。
- 相机私有元数据并未全面适配。缺少明确标签的 Log 仍需用户核对；不会依据灰片外观猜曲线。通用色彩转换不替代相机专属 Log 还原 LUT。
- 位图字幕的改时序和烧录仍需先 OCR，当前明确阻止；ASS 事件时间会映射，但卡拉 OK、动画等正文内部时间参数尚未重新计算。
- 无损裁切仍要求关键帧边界，音频还受音频包边界限制；未实现非关键帧处的局部重编码拼接。
- 目标体积是单遍码率预算，不保证逐字节命中；16-bit 无损输出组合未新增，不能用提高位深恢复原片不存在的层次。
- 尚未做真实相机的全格式矩阵、长片压力测试或专业 HDR 显示器验收。1D 实时预览仍使用可运行但已被 Apple 标为弃用的 Core Image Kernel Language 接口，后续应迁移到 Metal。

本次未涉及新的创意特效、多素材工程、撤销/重做或自动保存。
